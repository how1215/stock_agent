# 盤前例行

每個交易日執行一次。把資料同步、盤前提要、自選股狀況整合成一份固定格式的回報。

使用者說「盤前」、「今天要注意什麼」、「跑一下例行」、或直接 `/skill:premarket` 時執行。

## 步驟（依序，不要跳）

**步驟 1：呼叫 `stock_market({})`**

取得大盤收盤，同時觸發當日資料落地。

這步不能跳過。`stock_briefing` 讀既有報告時完全不碰資料層（實測 0 個 HTTP 請求），
所以只呼叫 briefing 不會把當日資料存下來。本專案的歷史資料只能靠每日抓取累積
（端點不接受日期參數，漏掉的交易日補不回來），這步就是累積的觸發點。

**步驟 2：呼叫 `stock_briefing({})`**

讀今天的盤前提要。它已包含大盤、市場寬度、自選股逐檔判讀、市場焦點。

- 今天已有報告 → 即時回傳（`source: cache`）
- 今天還沒有報告 → 它會自己生成，實測約 80 秒。這是每天第一次執行的正常情形。
  呼叫前先跟使用者說一句「今天還沒產生報告，要等約 80 秒」，不要默默讓他等
- 不要為了「確保最新」而加 `refresh: true`。只有使用者明確要求重新產生時才用
  （例如剛改過自選股想重跑）。若那時回報 `source: skipped`，表示沒有更新的交易日
  資料，既有報告仍然有效，照用即可

**步驟 3：按下面的模板回報**

不要只是把報告原文貼回去。報告是給人讀的完整資料，你的工作是濃縮成今日行動重點。

## 輸出模板

```
## 盤前提要（依據 <交易日> 收盤）

**大盤**
<加權指數收盤與漲跌，一行>
<市場寬度：漲跌家數、漲停跌停家數，一行>

**自選股**
<判斷軸是什麼，一句>
<逐檔：代號 名稱｜判斷｜一句理由。只列判斷有意義的，不要全部照抄>

**市場焦點**
<漲幅、跌幅、成交金額前段裡值得一提的，各一到兩檔，不要三個清單全貼>

**今日關注**
<兩到四點。從上面的數據推出「今天開盤該留意什麼」，每一點都要能對回具體數字>
```

## 紀律

**日期。** 報告有兩個日期且不同：報告日（今天）與依據的交易日（前一交易日）。
一律講交易日，不要說「今天的數據」。TWSE 的發布延遲比想像長 — 實測交易日晚間
八點都還拿不到當日收盤，所以「今天」幾乎永遠是指前一交易日。

**判斷軸。** 自選股的「符合／不符合」是針對報告裡那一行「判斷軸」判的。
不講判斷軸就說某檔「符合」是沒有意義的。

**數字。** 全部照抄工具回傳值。漲跌幅、張數、億元都已經算好，不要自己再算，
也不要補上工具沒給的數字。

**不給投資建議。** 「今日關注」是指出數據上值得留意的地方，不是建議買賣，
也不要預測走勢。結尾附一句：以上為公開數據整理，非投資建議。

## 使用者接著可能想問的

例行跑完後，若使用者要追問，用對應的工具而不是重跑例行：

- 某幾檔的細節 → `stock_quote`
- 排名或數值篩選（漲幅前 N、成交量最大）→ `stock_screen`
- 描述性條件（「收在最高、買盤強勢」）→ `stock_scan`，很慢，先提醒
- 調整關注名單 → `stock_watchlist`（`add` / `remove`；清空要請使用者用 CLI）
